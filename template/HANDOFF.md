# Handoff

The handoff recorder or development agent prepares this from actual feedback. The tester need not write another form. A short handoff needs an original round/item link, the needed decision or next action and role, and actual handoff status. Add a summary only when it helps select or connect items; do not require a full retelling or the whole program repository.

Use the kit language from [README.md](README.md#kit-identity). Keep quoted evidence exact, preserve its source, and label translations. Unknown and Undetermined are valid gaps; they do not block acceptance of incomplete feedback.

## Handoff entry

- Actual original round and item [required]: [Actual feedback starter](FEEDBACK_%23%23%23%23.md#item) — Not run; replace with the confirmed version filename and relevant round/item anchor before handoff.
- Needed decision or next action [required]: Unknown — no actual feedback yet.
- Responsible role [required]: Unknown.
- Handoff status [required]: Draft — no transmission or review recorded.
- Status updated by, with evidence [required]: Unknown.
- Summary [optional]: Not supplied.

Repeat the entry only for a distinct handoff need. If no follow-up is needed, record “No further action” with its basis instead of inventing work. The original feedback is the source of truth; preserve distinctions between observation, feeling, tester expectation, request, and hypothesis. Do not make a summary more certain than its source. Never treat [the fictional example](FEEDBACK_TEMPLATE.md) as a record or evidence.

### Prior-item decisions

When a handoff item relates to [mapped prior context](RUN.md#prior-context-to-current-scenarios), retain its original reference and actual feedback link. Briefly record the current behavior/accepted alternative or known limit, decision or proposed action, and source/confirming role. Unknown is valid; do not imply an unconfirmed decision is accepted or a retest passed. Keep observed discomfort in the original feedback even if behavior is intended or accepted. No prior context requires no extra entry or history retrieval.

## Attachment return review

Only when returning attachments, review the actual selected return copies within existing authority and capabilities. This review is separate from initial kit inclusion review. Follow the [item/source/copy mapping](FEEDBACK_%23%23%23%23.md#evidence-mapping); every included copy needs an actual item and a factual description, while source evidence may remain unattached.

- Actual return copies reviewed, relative links, and linked feedback items: None — no attachments selected.
- Reviewer role, actual scope and method (contents and applicable metadata): Not run — no attachments selected.
- Findings/result and exclusions or inspection limits: None — no review performed.

Cover all included types within capabilities, including visible screenshot/image contents, media contents, and metadata as applicable; text inspection alone does not establish visual/media review. Withhold unsafe or unreviewed copies, including unsupported contents, and record exclusions/limits without reproducing unsafe material. Exclude orphan attachments. Finish the report even when attachments are withheld. Before first returning an optional archive, review its actual members, metadata, and path layout against the mapped permitted return list and record the scope, method, result, and limits above; loose-file review does not cover the archive. Withhold unsafe or unreviewed archives while finishing the report. Re-review changed return copies and any changed return archive; earlier review does not cover modified contents. No attachments means a short None-with-basis record is sufficient; no scanner, new file, archive, or extra test is required.

## Status and return

Use Draft, Prepared for delivery, Sent, or Reviewed. Prepared is not sent. Mark Sent only after actual authorized transmission, with its basis. Mark Reviewed only with evidence of recipient review; Reviewed does not mean fixed, resolved, or retested successfully. Preserve attributed updates rather than rewriting original feedback.

- Actual saved feedback and handoff locations [required at closeout]: Unknown — confirm saved files before reporting them.
- Minimal return list [required at closeout]: Actual version feedback and this handoff; optional necessary, permitted attachments only. Confirm actual names before returning.
- Attachments and limits [required presence or absence; files optional]: None — none recorded.
- Not run, unresolved, and remaining work [required at closeout]: Unknown — use the actual feedback round's finish record as the basis.

Use relative links to actual kit files when filling these fields. Do not create links to nonexistent attachments. Other return files require a stated need and permitted scope; neither `repo/` in full nor the fictional example is automatically returned. Finishing testing does not authorize sending. Follow [the finish sequence](README.md#when-the-user-declares-testing-finished), report actual saved paths and remaining work, and describe any save or delivery failure accurately.
